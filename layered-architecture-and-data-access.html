    9. Layered Architecture and Data Access

    The previous examples kept their data in memory. A real application stores it in a database and is organized into layers (see the diagram in the introduction):

    • the web layer (controllers, views): read the request, call the business layer, select the view;
    • the business layer: business rules;
    • the DAO layer (*Data Access Object*): database queries.

    Each layer is aware only of the layer below it, and as few of its details as possible: the web layer is unaware of SQL, and the business layer is unaware of HTML. This separation makes each layer easier to understand, test, and evolve. Example 28 applies this to managing a list of people: it is, on a smaller scale, the management of doctors and clients from the case study.

    In [Python], database access is organized across several layers:

    • The DB-API standard (PEP 249) defines the common interface for database drivers: open a connection, execute a SQL command, and read rows. For [MySQL] (and [MariaDB]), we use [PyMySQL], a driver written entirely in [Python], which installs without a compiler;
    • [SQLAlchemy] is the most widely used data access library in [Python]. It has two levels. Its core (*Core*) manages connections (including a connection pool, which keeps a few connections open and lends them to queries, since opening a connection is costly) and constructs SQL statements from [Python] expressions, regardless of the SGBD. Its ORM (*Object-Relational Mapper*) maps [Python] classes (the entities) to database tables and transforms the read rows into objects.

    This is equivalent to [JDBC], [JPA] and [Hibernate] to [Java], or [Entity Framework Core] to [C#]. The [Flask-SQLAlchemy] extension slightly simplifies the configuration of [SQLAlchemy] in a [Flask] application; we use [SQLAlchemy] directly, which demonstrates what is happening and keeps the business layers and DAO independent of [Flask].

    The example requires a running [MySQL] (or [MariaDB]) server: the appendix explains how to install one using [Laragon].

from pathlib import Path

from flask import Blueprint, Flask
from flask_wtf.csrf import CSRFProtect
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

from controllers.personnes import personnes
from dao.personnes_dao import PersonnesDao
from metier.personnes_metier import PersonnesMetier

BOOTSTRAP = Path(__file__).resolve().parent.parent / "commun" / "bootstrap"


def create_app():
    app = Flask(__name__)
    app.jinja_env.trim_blocks = True
    app.jinja_env.lstrip_blocks = True
    app.config.from_pyfile("config.py")
    app.config.from_prefixed_env()

     # Database access: the "engine" of SQLAlchemy manages a POOL of connections
     # (connections opened once and then reused from one request to the next).
     # pool_pre_ping: a connection is tested before being reused
    moteur = create_engine(app.config["DATABASE_URL"], echo=app.config["SQL_ECHO"],
                           pool_pre_ping=True)
     # the session factory; expire_on_commit=False: the read objects remain
     # usable after the transaction ends (by the view, in particular)
    sessions = sessionmaker(moteur, expire_on_commit=False)

     # Layer assembly: DAO -> business layer; the web layer only recognizes the business layer
    app.extensions["metier"] = PersonnesMetier(sessions, PersonnesDao())

    app.register_blueprint(Blueprint("bootstrap", __name__, static_folder=BOOTSTRAP,
                                     static_url_path="/bootstrap"))
    app.register_blueprint(personnes)
    CSRFProtect(app)
    return app


if __name__ == "__main__":
    create_app().run(port=5000, debug=True)
    • Lines 26–27: The *engine* of [SQLAlchemy] is the object that manages connections to a database and the connection pool. It is created once, at startup; the first connection is opened only upon the first request. [pool_pre_ping=True] checks a connection from the pool before reusing it: a [MySQL] server closes connections that have been inactive for too long, and the application would otherwise receive an error;
    • Line 30: A session of type ORM is the object used to read from and write to entities; it borrows a connection from the pool and tracks the entities it has read to detect changes to them. [sessionmaker] creates a session factory, each call to which will produce a session. By default, at the end of a transaction, the session “expires” the entities (it forgets their values, to read them again the next time they are used). [expire_on_commit=False] prevents this: the entities returned by the business layer remain usable after the transaction, by the view that displays them;
    • line 33: assembling the layers: the business layer receives the session factory and the DAO layer. The web layer will only be aware of the business layer;
    • line 38: Anti-CSRF protection for the entire application (Example 21).

from sqlalchemy import String
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


# the parent class of all entities: SQLAlchemy stores the
# the class-to-table mapping for each of its child classes
class Base(DeclarativeBase):
    pass


class Personne(Base):
     # the table name
    __tablename__ = "personnes"

     # the primary key, generated by the database (AUTO_INCREMENT); SQLAlchemy re-reads
     # its value after each INSERT. Mapped[int]: the Python type of the column
    id: Mapped[int] = mapped_column(primary_key=True)
     # the optimistic lock: see __mapper_args__ below
    version: Mapped[int] = mapped_column()
    prenom: Mapped[str] = mapped_column(String(30))
    nom: Mapped[str] = mapped_column(String(30))
    age: Mapped[int]

     # version_id_col: SQLAlchemy increments the version number with each UPDATE, and adds
     # the condition "AND version = <read value>"
    __mapper_args__ = {"version_id_col": version}

    def __init__(self, prenom: str, nom: str, age: int):
        self.prenom = prenom
        self.nom = nom
        self.age = age
    • lines 8–9: All entities in an application inherit from the same base class, derived from [DeclarativeBase]. [SQLAlchemy] stores the description of each entity (its table, its columns) in this class: this is the declarative model;
    • line 14: the table associated with the class;
    • line 18: a column is declared by an attribute annotated with [Mapped[type]]: the column’s type, [Python]. [mapped_column] specifies its characteristics: in this case, the primary key. By default, an integer primary key is generated by the database ([AUTO_INCREMENT]): [SQLAlchemy] re-reads its value after each [INSERT];
    • Lines 21–23: [String(30)] specifies the column length (useful if [SQLAlchemy] were to create the table itself). A column with no special characteristics can simply use the annotation ([age]). The type [Mapped[str]] makes the column required ([NOT NULL]); [Mapped[str | None]] would make it optional;
    • line 27: [version_id_col] designates the version column: [SQLAlchemy] increments it with each [UPDATE], and adds the condition [AND version = <la valeur lue>] to it. If another query has modified the row in the meantime, its version has changed; [UPDATE] does not modify any rows, and [SQLAlchemy] throws a [StaleDataError] exception. This is an optimistic lock: nothing is blocked, but concurrent modifications are detected;
    • Lines 29–32: a constructor to create a person in a single line.

    # dao/personnes_dao.py: the DAO layer, requests, no business rules.
# Each method receives the SESSION from SQLAlchemy, opened by the layer
# business layer: all requests for the same operation thus share the same
# connection and the same transaction
from sqlalchemy import delete, select
from sqlalchemy.orm import Session

from entities.personne import Personne


class PersonnesDao:

     # SELECT ... FROM people ORDER BY last name, first name
    def lister(self, session: Session) -> list[Personne]:
        return list(session.scalars(select(Personne).order_by(Personne.nom, Personne.prenom)))

     # SELECT ... WHERE id = ?; None if the person does not exist
    def lire(self, session: Session, id: int) -> Personne | None:
        return session.get(Personne, id)

     # a person with the same first and last name, other than [sauf_id]:
     # SELECT ... WHERE first_name = ? AND last_name = ? AND id <> ? LIMIT 1
    def homonyme(self, session: Session, prenom: str, nom: str, sauf_id: int = 0) -> Personne | None:
        requete = select(Personne).where(Personne.prenom == prenom, Personne.nom == nom,
                                         Personne.id != sauf_id).limit(1)
        return session.scalars(requete).first()

     # INSERT (new person): the person is added to the session, and
     # flush sends TOUT DE SUITE the command SQL (not to COMMIT)
    def ajouter(self, session: Session, personne: Personne) -> Personne:
        session.add(personne)
        session.flush()
        return personne

     # DELETE FROM people WHERE id = ?
    def supprimer(self, session: Session, id: int):
        session.execute(delete(Personne).where(Personne.id == id))

    The DAO layer contains only queries, with no business rules. Each method receives the session opened by the business layer: all queries for a single business operation thus share the same connection and the same transaction.

    • Line 15: [select(Personne)] constructs a query ([SELECT]) on the "people" table; [order_by] sorts it. The columns are written as attributes of the class ([Personne.nom]): the editor can verify their names, and no SQL is written by hand. [session.scalars(...)] executes the query and returns the entities constructed from the read rows;
    • line 19: reading by primary key, or [None];
    • lines 23–26: [where] adds conditions, written using the operators from [Python] ([==], [!=]): [SQLAlchemy] translates them into SQL, with parameters (the values are never copied into the text of the SQL command, which makes SQL injection impossible). [first()] returns the first entity, or [None];
    • lines 30–33: [session.add] assigns a new entity to the session; [flush] immediately sends [INSERT] to the database (without [flush], it would go to [COMMIT]). The database then generates the ID, which [SQLAlchemy] stores in the entity;
    • line 37: a [DELETE], constructed in the same way.

    # business/personnes_metier.py: the MÉTIER layer and the business rules—and only those.
# Each method opens its own TRANSACTION: validated (COMMIT) at the end of the block
# with, rolled back (ROLLBACK) if an exception occurs
from sqlalchemy.exc import IntegrityError
from sqlalchemy.orm import sessionmaker
from sqlalchemy.orm.exc import StaleDataError

from dao.personnes_dao import PersonnesDao
from entities.personne import Personne
from metier.donnees import DonneesPersonne
from metier.exception import MetierException

HOMONYME = "Une personne porte déjà ces prénom et nom."
MODIFIEE = "Cette fiche a été modifiée entre-temps : rechargez-la."
INCONNUE = "Cette personne n'existe pas (ou plus)."


class PersonnesMetier:

     # sessions: the session "factory" SQLAlchemy (see app.py)
    def __init__(self, sessions: sessionmaker, dao: PersonnesDao):
        self._sessions = sessions
        self._dao = dao

    def lister(self) -> list[Personne]:
         # sessions.begin(): a session ET commits its transaction; the `with` block closes them
        with self._sessions.begin() as session:
            return self._dao.lister(session)

    def lire(self, id: int) -> Personne:
        with self._sessions.begin() as session:
            return self._lire(session, id)

    def ajouter(self, donnees: DonneesPersonne) -> Personne:
        try:
            with self._sessions.begin() as session:
                 # Rule 1: No two people can have the same first and last names
                if self._dao.homonyme(session, donnees.prenom, donnees.nom):
                    raise MetierException(HOMONYME)
                return self._dao.ajouter(session, Personne(donnees.prenom, donnees.nom, donnees.age))
        except IntegrityError as e:
            raise self._traduire(e)

    def modifier(self, id: int, version: int | None, donnees: DonneesPersonne) -> Personne:
        try:
            with self._sessions.begin() as session:
                personne = self._lire(session, id)
                 # Rule 2: Do not modify a record that has been modified in the meantime by someone else
                if personne.version != version:
                    raise MetierException(MODIFIEE)
                if self._dao.homonyme(session, donnees.prenom, donnees.nom, id):
                    raise MetierException(HOMONYME)
                 # The entity being read is “tracked” by the session: simply
                 # modify it; `flush` sends the UPDATE immediately
                personne.prenom = donnees.prenom
                personne.nom = donnees.nom
                personne.age = donnees.age
                session.flush()
                return personne
        except StaleDataError:
             # the UPDATE "WHERE id = ... AND version = ..." did not modify any rows
            raise MetierException(MODIFIEE)
        except IntegrityError as e:
            raise self._traduire(e)

    def supprimer(self, id: int) -> Personne:
        with self._sessions.begin() as session:
            personne = self._lire(session, id)
            self._dao.supprimer(session, id)
            return personne

    def _lire(self, session, id: int) -> Personne:
        personne = self._dao.lire(session, id)
        if personne is None:
            raise MetierException(INCONNUE)
        return personne

     # two simultaneous insertions: the database’s uniqueness constraint rejected the
     # second one; e.orig: the original error, the one from the driver PyMySQL
    @staticmethod
    def _traduire(e: IntegrityError) -> Exception:
        if "unq_personnes_prenom_nom" in str(e.orig):
            return MetierException(HOMONYME)
        return e
    • Line 27: Each method opens its own session and transaction: [sessions.begin()] returns a session with a transaction that has been started. At the end of the [with] block, the transaction is committed ([COMMIT]) and the session is closed; if an exception occurs within the block, the transaction is rolled back ([ROLLBACK]): none of the changes made within the block are retained. The business layer thus determines the scope of transactions: one business operation equals one transaction;
    • lines 34–42: Rule No. 1: No two people may have the same first and last names. The business layer checks this rule before writing to the database and raises a [MetierException] if it is not met. But this check is not sufficient: two simultaneous requests could both verify that there are no namesakes, and then both proceed to insert the data. The database’s uniqueness constraint then rejects the second [INSERT], and [SQLAlchemy] triggers a [IntegrityError], which the [_traduire] method transforms into the same [MetierException]. The database is the last line of defense;
    • lines 44–64: Rule No. 2: Do not modify a record that has been modified in the meantime by someone else. The update form carries the version of the record that was read (in a hidden field); if it differs from the current version, the record has changed since it was displayed. Here again, the database (via the optimistic lock) detects cases where a concurrent modification occurs between the read and the [UPDATE]: this is the [StaleDataError] exception. Note that the modification is performed simply by changing the attributes of the read entity: the session tracks this, and [flush] sends a [UPDATE] containing only the modified columns;
    • lines 66–70: Deleting a person results in the confirmation message;
    • lines 72–76: A nonexistent person is a business error;
    • lines 80–84: A static method does not accept either an object or a class; it is simply a function defined within the class. [e.orig] is the original exception, that of the driver [PyMySQL], whose message contains the name of the violated constraint. Another integrity error is reported as-is: this is not a business error, but a programming error.
