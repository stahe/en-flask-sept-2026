    5. Internationalization

    An internationalized application displays its text in the user's language. The case study is in French and English. The principle is simple: the views no longer contain text, but rather keys ([MENU.ACCUEIL]), and a dictionary for each language associates a text with each key. The selected language is stored in a cookie.

    The [Flask] ecosystem offers an extension for this purpose, [Flask-Babel], which relies on the standard translation system [gettext]: texts are extracted from the code by a tool, translated into [.po] files, and then compiled into [.mo] files. It is a powerful system, but it requires specific tools and a compilation step. Instead, we’ll write a small class that reads JSON dictionaries: These are the same files as the [ASP.NET Core MVC], [NestJS], and [Spring MVC] versions from the case study, and their format can be read and written without any special tools. The [Babel] library, on the other hand, is still used for formatting dates and amounts (Example 16).

    # translation/traducteur.py: the translation service
import json
import re
from pathlib import Path

from flask import g


class Traducteur:

    LANGUES = ("fr", "en")
    LANGUE_PAR_DEFAUT = "fr"

     # {name}: a parameter in a text
    PARAMETRE = re.compile(r"\{(\w+)\}")

    def __init__(self, dossier: Path):
         # language -> (full key "ACCUEIL.BONJOUR" -> text)
        self._dictionnaires: dict[str, dict[str, str]] = {}
        for langue in self.LANGUES:
            with open(dossier / f"{langue}.json", encoding="utf-8") as fichier:
                self._dictionnaires[langue] = self._aplatir(json.load(fichier))

     # the supported language corresponding to [code]: "en" -> "en"; "de" or None -> "fr"
    @classmethod
    def langue(cls, code: str | None) -> str:
        return code if code in cls.LANGUES else cls.LANGUE_PAR_DEFAUT

     # translate("ACCUEIL.BONJOUR", name="Marie") -> "Hello Marie!", in the
     # language of the current request (g.langue, see app.py)
    def traduire(self, cle: str, **parametres) -> str:
         # If a key is missing, the key itself is displayed: an omission is visible on the screen
        texte = self._dictionnaires[g.langue].get(cle, cle)
         # Each {name} is replaced by the value of the parameter with the same name
        return self.PARAMETRE.sub(
            lambda m: str(parametres.get(m.group(1), m.group(0))), texte)

     # { "MENU": { "ACCUEIL": "Home" } } -> { "MENU.ACCUEIL": "Home" }
    @classmethod
    def _aplatir(cls, noeud: dict, prefixe: str = "") -> dict[str, str]:
        resultat = {}
        for cle, valeur in noeud.items():
            cle_complete = f"{prefixe}.{cle}" if prefixe else cle
            if isinstance(valeur, dict):
                resultat.update(cls._aplatir(valeur, cle_complete))
            else:
                resultat[cle_complete] = valeur
        return resultat
    • lines 11–12: supported languages and the default language—class attributes shared by all objects of the class and accessible without an object ([Traducteur.LANGUES]);
    • line 15: the regular expression for a parameter: a curly brace ([\{], preceded by a [\] because the curly brace has a specific meaning in regular expressions), one or more word characters ([\w+]), and a closing curly brace. The parentheses capture the parameter name. [re.compile] parses the expression once and for all;
    • lines 17–22: the constructor reads the dictionaries once, when the service is created. [json.load] converts the contents of a JSON file into [Python] objects (nested dictionaries). [with open(...) as fichier] opens the file and ensures it is closed at the end of the block; [encoding="utf-8"] is essential, because the default encoding depends on the system (under [Windows], it is not always [UTF-8]);
    • Lines 25–27: A class method ([@classmethod] decorator) takes the class ([cls]) instead of an object; it is called on the class: [Traducteur.langue("en")]. It returns the supported language corresponding to a code, or the default language if the code is unknown or missing;
    • lines 31–36: the translation of a key, in the language of the current query, read from [g.langue] (see Example 16). A key missing from the dictionary is displayed as-is: an omission is immediately visible on the screen. The parameters are received as named parameters ([**parametres]); the regular expression method [sub] replaces each parameter found in the text with the result of a function—in this case, an anonymous function ([lambda m: ...])—which receives the match found ([m]): [m.group(1)] is the captured name, [m.group(0)] is the full text [{nom}], which is retained if the parameter was not provided;
    • Lines 40–48: The nested JSON objects are “flattened” into a single dictionary, whose keys are the full keys: [{"MENU": {"ACCUEIL": "Accueil"}}] becomes [{"MENU.ACCUEIL": "Accueil"}]. The method is recursive: it calls itself for each nested object, using the current key as a prefix.

    # translation/formats.py: dates and amounts, formatted in the language of the request (see Example 16)
from datetime import date
from decimal import Decimal

from babel.dates import format_date
from babel.numbers import format_currency
from flask import g


# a date written out in full
def date_longue(jour: date) -> str:
    return format_date(jour, format="full", locale=g.langue)


# an amount in euros
def monnaie(montant: Decimal) -> str:
    return format_currency(montant, "EUR", locale=g.langue)

    The filters in Example 16, which this time use [g.langue]. [Babel] accepts a single language ([fr], [en]) as well as a language and a country ([fr_FR]); for [en], it applies U.S. conventions.

    # app.py: the application from Example 22
from pathlib import Path

from flask import Blueprint, Flask, g, request

from controllers.langue import COOKIE_LANGUE, langue
from controllers.pages import pages
from traduction import formats
from traduction.traducteur import Traducteur

# Bootstrap, used across the examples (see Example 15)
BOOTSTRAP = Path(__file__).resolve().parent.parent / "commun" / "bootstrap"


def create_app():
    app = Flask(__name__)
    app.jinja_env.trim_blocks = True
    app.jinja_env.lstrip_blocks = True
     # the translation service: the dictionaries, read UNE times at startup
    traducteur = Traducteur(Path(app.root_path) / "i18n")
    app.extensions["traducteur"] = traducteur
    app.register_blueprint(Blueprint("bootstrap", __name__, static_folder=BOOTSTRAP,
                                     static_url_path="/bootstrap"))
    app.register_blueprint(langue)
    app.register_blueprint(pages)

     # The language of each request: the language specified in the [langue] cookie, or French otherwise
    @app.before_request
    def fixer_langue():
        g.langue = Traducteur.langue(request.cookies.get(COOKIE_LANGUE))

     # in views: {{ t('CLE') }}, {{ day | date_longue }}, {{ price | currency }}
    app.add_template_global(traducteur.traduire, "t")
    app.add_template_filter(formats.date_longue)
    app.add_template_filter(formats.monnaie)
    return app


if __name__ == "__main__":
    create_app().run(port=5000, debug=True)
    • lines 20–21: the service, created once at startup. [app.root_path] is the application folder (that of [app.py]);
    • Lines 28–30: Before each action, the request language is set to the language of the [langue] cookie if one exists and is supported; otherwise, it defaults to French. [request.cookies] is the dictionary of cookies sent by the browser;
    • line 33: the service’s [traduire] method is made available to views as a global function under a short name, [t] (the second parameter of [add_template_global]). An object method is used like a function: [traducteur.traduire] is a method associated with the object [traducteur].

    # controllers/langue.py: language selection
from urllib.parse import urlsplit

from flask import Blueprint, abort, redirect, request

from traduction.traducteur import Traducteur

langue = Blueprint("langue", __name__)

COOKIE_LANGUE = "langue"


# GET /language/en: stores the selection in a cookie, then returns to the previous page
@langue.get("/langue/<code>")
def changer(code):
    if code not in Traducteur.LANGUES:
        abort(404)
    reponse = redirect(page_d_origine())
     # the cookie: valid for one year, unreadable by the JavaScript on the page (httponly),
     # never sent with a POST request originating from another site (same-site)
    reponse.set_cookie(COOKIE_LANGUE, code, max_age=365 * 24 * 3600, httponly=True,
                       samesite="Lax")
    return reponse


# the page from which the user came (Referer header), of which only the path is retained:
# redirecting to a full URL from the request would allow
# to redirect the user to another site ("open redirect" vulnerability)
def page_d_origine() -> str:
    url = urlsplit(request.headers.get("Referer", ""))
    chemin = url.path
     # "//site.com/..." would be interpreted by the browser as a URL
     # to a AUTRE site: also rejected
    if not chemin.startswith("/") or chemin.startswith("//"):
        return "/"
    return f"{chemin}?{url.query}" if url.query else chemin
    • line 16: an unknown language code: 404;
    • line 18: the action responds with a redirect to the page the user came from: the user is returned to that page, in the new language;
    • Lines 21–22: The response includes a cookie, which the browser will send back with every request. [max_age] is its lifetime, in seconds: one year. [httponly=True] makes it invisible to the [JavaScript] on the page; [samesite="Lax"] prevents the browser from sending it with a POST request originating from another site. Unlike the session cookie (example 20), this cookie is not signed: it’s not a problem if the user modifies it, as the server only accepts supported languages;
    • lines 29–36: the original page is specified by the [Referer] header in the request (the misspelled version, with a single [r], is the one used in the HTTP standard), which the browser populates with the URL from the page that contained the link. But this header comes from the client, which can put anything in it. Blindly redirecting to this address would turn our application into an *open redirect*: a malicious link bearing our domain name could send the user to a malicious site. Therefore, we retain only the path and parameters of URL ([urlsplit] breaks it down into its components), and we reject any path that begins with [//], which the browser would interpret as the address of another site.

    # controllers/pages.py: the actions are not language-aware; they
# provide data; the views translate and format it
from dataclasses import dataclass
from datetime import date
from decimal import Decimal

from flask import Blueprint, render_template

pages = Blueprint("pages", __name__)


@dataclass
class Produit:
    nom: str
    prix: Decimal


@pages.get("/")
def accueil():
    return render_template("pages/accueil.html", nom="Marie", aujourdhui=date(2026, 9, 23))


@pages.get("/produits")
def produits():
    return render_template("pages/produits.html", produits=[
        Produit("Clavier", Decimal("25")),
        Produit("Souris", Decimal("12.5")),
        Produit("Écran", Decimal("1149")),
    ])

    Actions are language-agnostic: they provide raw data (a name, a date, amounts). Translation and formatting are handled by the views.
